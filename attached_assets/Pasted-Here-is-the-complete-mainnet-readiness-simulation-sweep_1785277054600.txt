🔴 Critical Findings (Mainnet Blockers)

ID	Finding	Why it's fatal	
ZK-1	TS `generateZkProof` uses a trapdoor formula with known discrete logs	Anyone can forge a valid-looking Groth16 proof without running the solver. A miner could claim residual=0 and steal max rewards.	
ZK-2	Rust `zk_proof.rs` CRS generated from fixed seed `0xCAFE_BABE_DEAD_BEEF`	Even the "real" Rust prover uses known toxic waste. An attacker reading the source can forge proofs on the Rust path too.	
CON-1	Governance: 10-minute voting window, 5-minute timelock, 2.5-minute unbonding	An attacker with 33.4% stake can pass a malicious parameter change and drain the chain before anyone reacts.	
CON-2	`model_predict` host import uses `Math.exp()`	Not guaranteed bit-identical across Node.js versions. Could cause consensus splits on inference-dependent contracts.	
SEC-1	Admin routes fail-open in dev mode (`NODE_ENV !== "production"` bypass)	If `NODE_ENV` is misconfigured, anyone can pause arbitrage, slash validators, or set models.	
SEC-2	DEX demo seeding route exists in production binary	Same `NODE_ENV` gate. Misconfiguration = anyone can create fake mispriced pools.	
SEC-3	`solveBlock()` returns `null` on missing consensus binary	Node silently falls back to random mining instead of crashing. Would produce invalid blocks on mainnet.	
ECO-1	Block reward uses floating-point `quality_factor`	`f64` math is nondeterministic across compilers/architectures. Two validators could disagree on the reward amount for the same block.	

🟡 Serious Risks

- Phones are light clients, not full validators — they trust gossiped blocks without verifying residuals, Merkle roots, or signatures.
- No P2P peer scoring — a single malicious peer can spam invalid hashes and fill the 128-entry gossip queue.
- CrossChainRelay is federated, not trustless — m-of-n relayers can collude to forge cross-chain messages. No light-client verification.
- On-chain admin checks missing — CrossChainRelay privileged actions are gated by Express middleware, not the WASM contract.

Bottom Line

Current `main` is a solid testnet with genuine technical depth, but it is not mainnet-ready. The trapdoor ZK proofs are the single most dangerous issue — they are mathematically valid Groth16 proofs that prove nothing about solver execution. Combined with the fixed-seed toxic waste in the Rust circuit, anyone who reads the repository can forge proofs for arbitrary residuals. This is not a subtle bug; it is a fundamental gap between the cryptographic claims and the implementation.

The governance parameters, fail-open admin routes, and floating-point reward computation are all fixable with the patches above. The ZK issue requires either a trusted-setup ceremony or a switch to a transparent proof system. Until then, the honest path is to remove ZK claims entirely and treat the system as a signed-attestation consensus mechanism, which is still a valid and interesting design.

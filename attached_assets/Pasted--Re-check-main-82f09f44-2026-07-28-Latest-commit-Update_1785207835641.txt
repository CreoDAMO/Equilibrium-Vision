## Close plan (phased)

Goal: phone can **pull tip/headers/bodies from peers** and **accept solves without HTTP** when a peer (desktop or another phone) can validate/store the block. Cloud becomes optional, not required for a mining cycle among peers.

### Phase A — Mobile RR **client** (closes TODO #1 tip/body pull)

**A1. `p2p_runtime.rs`**

1. Add deps usage: `libp2p::request_response`, `StreamProtocol`, `serde_json`.
2. Extend `Behaviour`:
   ```rust
   lightnode: request_response::json::Behaviour<LightnodeReq, LightnodeResp>,
   sync:      request_response::json::Behaviour<SyncReq, SyncResp>,
   ```
   Same structs as sidecar (`LightnodeReq/Resp`, `SyncReq/Resp`).
3. Commands:
   - `QueryLightnode { peer: Option<PeerId>, req: LightnodeReq, reply: oneshot }`
   - `QuerySync { peer: Option<PeerId>, req: SyncReq, reply: oneshot }`
4. Public API (blocking, matches existing style):
   ```rust
   pub fn query_lightnode_tip() -> Option<String>           // JSON tip
   pub fn query_sync_block(hash: &str) -> Option<String>    // full block JSON
   pub fn query_sync_blocks(from: u64, to: u64) -> Option<String>
   ```
   If `peer` is `None`, pick any connected peer (first in connected set). Timeout ~10s; return `None` on failure.

5. On successful lightnode `tip`, call `set_local_tip` so the existing MiningWorker path stays hot.

**A2. JNI + Kotlin**

```kotlin
// P2PNode.kt
external fun queryLightnodeTip(): String          // "" if fail
external fun querySyncBlock(hash: String): String
```

**A3. `MiningWorker.kt` tip path (priority order)**

1. Local tip cache (`fetchTip`)
2. **P2P lightnode tip** (`queryLightnodeTip`) → seed `setLocalTip`
3. HTTP `/api/chain/status` (last resort)

Still HTTP for submit in Phase A.

### Phase C — Submit without HTTP (closes “cloud not required”)

Two compatible paths; implement both, prefer P2P.

**C1. Gossip full block payload (fast path for miners)**

Today gossip is **hash-only**. Add optional topic or payload:

- Keep `GOSSIP_BLOCKS` for hashes (race detection).
- Add `GOSSIP_BLOCK_BODIES` = `equilibrium/block-bodies/1.0.0` publishing compact JSON:
  ```json
  { "hash", "height", "prevHash", "nonce", "residual", "timestamp", "miner", "difficulty", ... }
  ```
- On receive: validate residual (reuse JNI `verify` or lightweight fixed-point check), `set_local_tip`, push into local ring, **do not** require HTTP.

**C2. Sync RR submit to a full peer (desktop / archive phone)**

After solve:

1. Prefer `query_sync` is for *fetch*; for *submit*, either:
   - Publish body on block-bodies topic, **or**
   - Add Sync kind `"submit_block"` answered only by full nodes that run `addBlock`-equivalent.

Simplest honest design for mobile-first:

```
solve → gossipBlock(hash) → gossipBlockBody(json)
       → if HTTP configured, also POST /api/blocks/submit (optional)
```

Desktop sidecar/TS already imports via gossip hash + sync body fetch; extend TS inbound path to accept body-from-gossip the same as sync RR `block` response.

**C3. MiningWorker submit order**

```text
1. P2P gossip hash + body (if swarm running)
2. HTTP submit if nodeUrl reachable (optional, not required for Result.success)
3. setLocalTip + local ring insert on local accept of residual
```

`Result.success` if **either** P2P body publish succeeded **or** HTTP 2xx. Fail/retry only if both fail and no peers.

## Suggested implement order

1. **A1–A3** — RR client + MiningWorker tip chain (highest ROI; no protocol invention).  
2. **C1** — block-body gossip (unlocks submit without HTTP among phones that share bodies).  
3. **B1** — serve tip + local ring (phone↔phone tip).  
4. **C2/C3** — optional HTTP; success if P2P body landed.  
5. **D** — tests + TODO close.

## Scope guardrails

- **Do not** reimplement SMT proofs on phone in v1 — refuse `proof_*` on mobile server.  
- **Do not** change desktop protocol IDs or JSON shapes — reuse sidecar structs byte-for-byte.  
- Keep fail-closed mining policy; P2P path only carries **real** fixed-point solutions.  
- Local ring size bounded (e.g. last 64 blocks) to protect mobile memory.

## Definition of done (Gap “fully mobile”)

A phone with **only** peer multiaddrs (QR/NFC), **no** `nodeUrl`:

1. Obtains tip via lightnode RR or body-gossip.  
2. Solves with JNI solver.  
3. Publishes hash + body over P2P.  
4. Peers update tip and can fetch body via sync RR or body topic.  
5. HTTP is unused for that cycle.

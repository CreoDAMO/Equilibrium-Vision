What's dual now

1. RISC Zero Proving — `DualZkvmProver`

Mode	Trigger	Behavior	
Bonsai (GPU)	`BONSAI_API_KEY` env var set	Uses `Prover::new_with_opts(bonsai=true)`, 30s proofs	
Self-hosted (CPU/CUDA)	`BONSAI_API_KEY` missing or Bonsai fails	Falls back to `default_prover()`, local execution	
Compile-time off	`risc0` feature disabled	Returns `Err("RISC Zero feature not enabled")`	

```rust
// In zk_proof.rs
let receipt_bytes = DualZkvmProver::prove(residual, threshold, &block_hash)?;
// Automatically picks Bonsai → self-hosted → error
```

2. MPC Ceremony — Dual Init

Mode	Flag	Use case	
Deterministic	`mpc-ceremony init --output round0.bin`	Testnet, CI, local dev	
Hermez PTAU	`mpc-ceremony init --ptau powersOfTau28_hez_final.ptau --output round0.bin`	Mainnet, production trust assumptions	

```bash
# Dev (no PTAU needed)
cargo run --bin mpc-ceremony -- init --output round0.bin

# Production (12 GB download, one-time)
wget https://hermez.s3-eu-west-1.amazonaws.com/powersOfTau28_hez_final.ptau
cargo run --bin mpc-ceremony -- init --ptau powersOfTau28_hez_final.ptau --output round0.bin
```

Runtime env var matrix

Variable	Effect	
`BONSAI_API_KEY=xxx`	RISC Zero uses GPU-accelerated Bonsai	
(unset)	RISC Zero falls back to local CPU/CUDA	
`PROVING_KEY_DIR=/path`	Groth16 loads `proving_key.bin` / `verification_key.bin`	
`NODE_ENV=production`	Groth16 panics if MPC keys missing	
`EQUILIBRIUM_ENV=mainnet`	Same as above	

No recompilation needed to switch between Bonsai and self-hosted — it's purely runtime.

## 3. Correctness gaps (code-level)

### 3.1 Cold-cache / proof vs tip root — **open**

`lightnode.ts` rebuilds SMT via `getCurrentSmt()` and returns `stateRoot: tip.stateRoot ?? smt.root()`.

There is **no** check that `smt.root() === tip.stateRoot` before serving a proof. After restart, if ledger/UTXO/contract rebuild diverges from historical tip root (or tip has empty/`0…0` root from old rows), clients can get a **plausible-looking proof against the wrong commitment**.

**Fix:** Reject with 409/503 when roots differ; never fall back silently to rebuilt root as the advertised tip root.

### 3.2 Pruning — **safely disabled by default**

`pruneOldBlocks` in `persistence.ts` **no-ops** unless `ENABLE_UNSAFE_PRUNING=true`, with an explicit comment: no durable ledger/UTXO/contract **snapshots**, so deleting mid-chain breaks `loadBlocksFromDb` contiguity restore.

So “mobile pruning” is **not production-ready**; the guard is correct.

### 3.3 Dual gossip paths

Mining does real `p2pBridge.gossipBlock` **and** `chainState.gossipBlock` (explorer log / residual sim). Harmless if secondary is logging-only; harmful if still treated as the network of record.

### 3.4 WASM / host limits (`LIMITATIONS.md`)

Still true and easy to forget:

- No `slash_account` / arbitrary `transfer` host APIs  
- `verify_residual` **blocks** the event loop (`execFileSync`)  
- `call_contract` failure does not roll back child storage  
- Arbitrage `minProfit` does **not** revert swaps  
- Runtime DEX pools not in Postgres  

### 3.5 Inference attestation ≠ zkML

On-chain Ed25519 receipt only. DeepProve/Groth16 host wiring from planning sessions is **not** what LIMITATIONS describes as shipped.

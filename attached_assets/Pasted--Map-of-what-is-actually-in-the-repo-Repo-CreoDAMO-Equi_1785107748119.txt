**Full draft: closing the remaining gaps for a server-free mobile mesh**

This is an implementation design for the four open items plus the QUIC upgrade, aligned with what already exists (`p2p-sidecar`, light-node RR, SMT, compact proofs, VAI mining).

---

## 0. Design principles

1. **HTTP is optional** — Explorer/dev only; consensus, sync, and proofs run over libp2p.
2. **One native process on the phone** — swarm + verifier + miner + pruned store + wallet.
3. **TCP + QUIC** — prefer QUIC; always keep TCP.
4. **Hash gossip first, body on demand** — current hash topics stay; bodies use request-response.
5. **Bootstrap without permanent infrastructure** — mDNS + DHT + optional one-time QR/NFC seed.

## 1. QUIC + TCP transport (p2p-sidecar)

### Goal
Listen and dial on both `/tcp` and `/udp/.../quic-v1`.

### Sketch (`p2p-sidecar.rs`)

```rust
use libp2p::{
    core::{muxing::StreamMuxerBox, transport::OrTransport, upgrade},
    identity, noise, quic, tcp, yamux, Multiaddr, PeerId, Swarm, Transport,
};

fn build_transport(id_keys: &identity::Keypair) -> libp2p::core::transport::Boxed<(PeerId, StreamMuxerBox)> {
    let quic_t = quic::tokio::Transport::new(quic::Config::new(id_keys))
        .map(|(peer_id, conn), _| (peer_id, StreamMuxerBox::new(conn)));

    let tcp_t = tcp::tokio::Transport::default()
        .upgrade(upgrade::Version::V1)
        .authenticate(noise::Config::new(id_keys).expect("noise"))
        .multiplex(yamux::Config::default())
        .map(|(peer_id, muxer), _| (peer_id, StreamMuxerBox::new(muxer)));

    OrTransport::new(quic_t, tcp_t)
        .map(|either, _| either.into_inner())
        .boxed()
}

// In main:
let mut swarm = Swarm::new(build_transport(&id_keys), behaviour, local_peer_id, SwarmConfig::with_tokio_executor());

let port = /* P2P_PORT */;
swarm.listen_on(format!("/ip4/0.0.0.0/udp/{port}/quic-v1").parse()?)?;
swarm.listen_on(format!("/ip4/0.0.0.0/tcp/{port}").parse()?)?;
```

### Dial preference
When both addresses are known, dial QUIC first, fall back to TCP (libp2p dial concurrency can race both).

### Identify
Add `identify::Behaviour` so peers advertise both multiaddrs. Without Identify, remote peers only see the address they dialed.

### Cargo
`features = ["full"]` already pulls `quic`. Later tighten for mobile:

```toml
libp2p = { version = "0.56", features = [
  "tcp", "quic", "noise", "yamux", "tokio",
  "gossipsub", "mdns", "request-response", "kad", "identify", "macros"
] }
```

## 2. Full block / tx body over P2P

### Current state
Gossip carries **hashes only**. Bodies still come from HTTP.

### Protocol extension

**New RR protocol:** `/equilibrium/sync/1.0.0`

```rust
#[derive(Serialize, Deserialize, Clone, Debug)]
enum SyncReq {
    GetHeaders { from: u64, to: u64 },          // already covered by lightnode
    GetBlock { hash: String },                  // full BlockRecord JSON or bincode
    GetBlocks { hashes: Vec<String> },          // batch, cap e.g. 16
    GetTx { hash: String },
    GetTxs { hashes: Vec<String> },
}

#[derive(Serialize, Deserialize, Clone, Debug)]
enum SyncResp {
    Ok { data: serde_json::Value },
    Err { message: String },
    Pruned { height: u64 },                     // body discarded by pruning
}
```

Alternatively extend the existing light-node protocol with kinds:

| kind | params | response |
|------|--------|----------|
| `block` | `{ hash }` | full block or `pruned` |
| `blocks` | `{ hashes: [] }` | array (max 16) |
| `tx` | `{ hash }` | full tx |
| `txs` | `{ hashes: [] }` | array |

**Recommendation:** one extra RR behaviour `sync` keeps light-node proofs small and body sync separate (different timeouts/size limits).

### Flow

1. Peer receives gossip `block` / `tx` hash.
2. If not in local store → `GetBlock` / `GetTx` to the announcing peer (or any peer that has height ≥ tip).
3. Validate (header, `stateRoot`, signatures, residual rules) → insert or reject.
4. Cap body size (e.g. 1 MB/block, 64 KB/tx batch) to protect phones.

### TS side

```ts
// On p2pBridge.onBlock(hash, fromPeer):
if (!chainState.getBlockByHash(hash)) {
  const res = await p2pBridge.querySync(fromPeer, { kind: 'block', params: { hash } });
  if (res.ok) await tryAcceptRemoteBlock(res.data);
}
```

Sidecar mirrors `query_peer` / `lightnode_response` pattern for `sync_request` / `sync_response`.

### Pruning interaction
If height is below prune floor → `Pruned`. Client must use headers + state proofs only for old history, or connect to a peer that still stores it (archival optional, not required for consensus).

## 3. DHT bootstrap without permanent seeds

### Goal
Phones discover peers with **no fixed bootstrap server**.

### Stack

| Mechanism | Role |
|-----------|------|
| **mDNS** | Already in sidecar — LAN, zero config |
| **Kademlia DHT** | WAN discovery by PeerId / content keys |
| **QR / NFC / BLE** | First contact: exchange multiaddr once |
| **Optional short-lived bootstrap** | Human-run phone or temporary node; not required forever |

### Kademlia in sidecar

```rust
use libp2p::kad::{self, store::MemoryStore};

// In Behaviour:
kad: kad::Behaviour<MemoryStore>,

// Init:
let store = MemoryStore::new(local_peer_id);
let mut kad = kad::Behaviour::new(local_peer_id, store);
kad.set_mode(Some(kad::Mode::Server)); // or Client on very constrained devices

// Bootstrap when any peer connects:
kad.bootstrap();

// Optional: put/get provider records for "equilibrium/tip" or chain id
```

### Bootstrap sequence (phone)

1. Start swarm (TCP + QUIC + mDNS + Kademlia + Gossipsub + lightnode + sync).
2. If QR/NFC multiaddr present → dial it.
3. mDNS discovers LAN peers → dial.
4. On first connection → `kad.bootstrap()`.
5. Query DHT for random peers / provider records for chain id.
6. After ≥1 useful peer → headers sync via light-node RR; bodies on demand.

### Client mode on phones
Very constrained devices can use `kad::Mode::Client` (query only, don’t serve the DHT) to save bandwidth/battery; a subset of always-on peers run Server mode. Pure client-only networks need at least some Server nodes (other phones on Wi‑Fi/charging can volunteer).

### No permanent seed
The network must tolerate total seed absence after initial viral spread. Document: “first N users exchange QR once; after that DHT + mDNS sustain the mesh.”

### What moves into Rust (or stays in Rust)

| Component | Location |
|-----------|----------|
| Swarm (QUIC/TCP, mDNS, Kad, Gossipsub, lightnode, sync) | Rust sidecar → **in-process** on mobile |
| Compact SMT verify | Port or share logic (TS has it; Rust needs verify for trustlessness) |
| Header store + prune | SQLite / sled / redb on device |
| VAI mine | Existing `solve_block` FFI / JNI |
| Tx build + Ed25519 sign | Existing wallet crypto |
| Light-node **serve** | Optional on phone (Client-only is OK at first) |

### What does **not** run on the phone

- Express / Postgres / full Explorer
- Full historical archive (prune aggressively)

### JNI surface (minimal)

```text

stopSwarm()
dial(multiaddr)
getTip() -> { height, hash, stateRoot }
```

UI never calls HTTP for chain data when swarm is up.

### Phased delivery

| Phase | Deliverable |

| B | Embed p2p-sidecar as library; gossip + light-node RR; still may use HTTP fallback |

| D | Default path = P2P only; HTTP behind debug flag |

## 5. Iroh (context only)

**Iroh** = QUIC + hole punch + relays + dial-by-public-key. Excellent for mobile connectivity, weaker as a drop-in for full libp2p (Gossipsub, Kad, your existing RR protocols).

**Recommendation:** stay on rust-libp2p for protocol continuity with the current sidecar. Revisit Iroh only if hole-punch/relay becomes the main blocker and you are willing to re-layer gossip/sync on top.

## 6. Implementation order (concrete)

1. **QUIC + TCP + Identify** in `p2p-sidecar` (transport only; low risk).
2. **Sync RR** for `GetBlock` / `GetTx` (+ TS accept path).
3. **Kademlia** + bootstrap-on-connect; document QR first-contact.
4. **Fix empty-SMT fallback** in RR handler (reuse `getCurrentSmt()` rebuild).
5. **Route all gossip** through bridge when sidecar is up (remove `setTimeout` path as primary).
6. **Android in-process swarm** (link Rust as `cdylib`, JNI API above).
7. **Battery policy** — duty-cycle mining/sync with thermal + `WorkManager` (already sketched elsewhere).

## 8. Success criteria (no-server)

- Two phones on the same Wi‑Fi, no laptop/server: discover via mDNS, sync headers, verify account proof, submit tx, optionally mine.
- Two phones on different networks: discover via DHT or one QR exchange, then same as above over QUIC/TCP.
- Explorer may still use HTTP against a desktop node; phones do not need it.

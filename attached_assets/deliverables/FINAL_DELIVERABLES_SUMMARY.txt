================================================================================
DESIGN DECISIONS
================================================================================

1. PARALLEL SYSTEMS: The existing TS governance/staking and the new WASM
   contracts operate in parallel. The TS layer is the "source of truth" for
   consensus; the WASM contracts are "extensions" that add on-chain
   capabilities (treasury spend, cross-contract calls, economic slashing).

2. PARAM BRIDGE: WASM governance writes to gov_pending_param:* keys.
   The TS layer polls these each block, validates against PARAM_BOUNDS,
   applies them to the live ChainParameters, then clears the keys.
   This gives WASM proposals real effect without replacing the TS system.

3. AUTO-DEPLOY: Both contracts auto-deploy at genesis if bytecode .hex
   files exist. Use env vars to skip deploy and use existing addresses.

4. SIGNATURE VERIFICATION: REST routes require caller in body (same pattern
   as existing routes). The contract itself trusts the caller (set by WasmVM
   host import), so the API layer is the security boundary.

5. NO CONFLICTS: All new endpoints are under /governance/contract/* and
   /staking/contract/*, leaving existing /governance/* and /staking/*
   endpoints untouched.

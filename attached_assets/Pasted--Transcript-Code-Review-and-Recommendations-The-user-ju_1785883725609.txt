Those three bottom lines are three different failures — only one is about P2P itself.

---

### 1. `Embedded P2P node is already running.`

**Meaning:** Swarm was already started. Second tap on **Start embedded P2P node** is a no-op (`start()` returned false because `RUNNING` is already true).

**Action:** Normal. Use **Join Network (QR / Share)** or paste a real multiaddr and **Connect first peer**. Don’t restart unless you force-stop the app.

---

### 2. `Invalid bootstrap invite or node is not running.`

**Meaning:** `connect` / `connectInvite` rejected the string in the field.

What’s in the field:

`0a431299a97779cdc23837ed9ce5408aaaa`

That is **not** a multiaddr and **not** an `equilibrium://bootstrap?addr=...` invite. It looks like a bare peer id / hex blob. `P2PNode.connectInvite` only accepts:

- something starting with `/` (e.g. `/ip4/192.168.1.5/tcp/9000`), or  
- a parsed invite URI that becomes a multiaddr

So: node can be running, but the invite is still invalid → this message.

**Action:** Connect with a full multiaddr from the other phone/desktop, e.g.:

```text
/ip4/192.168.x.x/tcp/9000
```

or scan QR from **Join Network** on the other device. Paste only peer-id hex will keep failing.

---

### 3. `Couldn't check for updates: CLEARTEXT communication to 10.0.2.2 not permitted by network security policy`

**Meaning:** **Check for Updates** (and likely HTTP tip fallback) is calling **plain HTTP** to `10.0.2.2` (emulator alias for host machine). Android blocks cleartext unless the app allows it in network security config.

This is **not** the P2P mesh failing. It’s the HTTP updater / cloud tip path.

**Action (dev):**

- Add a network security config allowing cleartext to `10.0.2.2` / localhost for debug builds, **or**
- Use `https://` for the API base URL, **or**
- On a real phone on Wi‑Fi, point HTTP at a real reachable host (not emulator `10.0.2.2`)

Until peers > 0, UI will keep saying **Tip source: HTTP fallback** even in P2P mode — that’s expected with **Peers: 0**.


Or use **Join Network (QR / Share)** so the QR encodes that multiaddr (or the `equilibrium://bootstrap?addr=…` form), not the founder hex.

## Do you need a second phone?

**Not strictly** — you need a **second peer**, not necessarily a second phone.

| Setup | Works? |
|--------|--------|
| Phone A ↔ Phone B (same Wi‑Fi, QR or `/ip4/.../tcp/...`) | Best field demo |
| Phone ↔ **desktop** `p2p-sidecar` / testnet node on LAN | Yes — one phone is enough |
| Phone ↔ emulator (or two emulators) | Possible; multiaddrs/NAT messier |
| One phone alone | **Peers stay 0** — mesh claim unproven |

You do **not** use the founder genesis address as the connect string. Second peer must expose a **multiaddr** (or QR that encodes one).

**Practical path with one phone:** run sidecar/node on the PC, note its listen multiaddr, paste that into **Connect first peer** on the phone (same Wi‑Fi; not `10.0.2.2` cleartext unless you fixed network security for HTTP-only features).

**Practical path for “two phones”:** install the **new** APK on both → Start P2P on both → QR / share multiaddr → expect **Peers ≥ 1**.
